  11. OIIO link shims — two dllimport inline members (string_view default ctor, TypeDesc::is_array) are absent from the 2020 DLL; VS2019 always inlined them, MSVC 14.5x emits __imp_ calls. scripts/shims builds hand-written bodies (header-verified layouts) and /ALTERNATENAME routes only-unresolved lookups to them.
  12. Cloudflare-fronted; cuts transfers with HTTP 429 after roughly 100–150 MB bursts (residential IP) or near-instantly (Azure runner IPs shared with other tenants).
  13. IP lottery model (runs #2/#19/#20 evidence): a fresh runner IP can pull the full 8 GB in one ~21-minute sitting (probe #2); a burned one gets ~20 MB and then instant 429s for many minutes — 30–60 s backoffs never lifted it (#19/#20).
  14. svn update on an interrupted checkout can return success while files are missing. svn checkout --force re-run in the same wc is faithful: existing files kept, missing re-fetched (verified locally: 142→196 MB resume of python/37).
  15. Each attempt banks its partial tree (win64-vc15-r62438-<run> keys, saved if: always()), and re-attempts resume from the newest one.
  16. Subtrees are ordered big-first, so even ~20 MB-budget attempts bank the most valuable bytes first.
  17. A burned IP fails fast (~8 min) with exit 2 and a clear "re-run me" error — re-run the failed job (Re-run failed jobs on the run page, or push anything to main) until an attempt lands a fresh IP with real budget. Probe #2 shows one lucky IP finishes the whole remaining fetch in a single pass.
  18. Worst case, ~10 attempts compound the ~2 GB selective set at ~50 MB/run — tedious but converging. The 7 small subtrees are already banked as of run #20.

Confirmed workflow bugs

  1. Rename step self-sabotage. apply-branding.py inserts set_target_properties(blender PROPERTIES OUTPUT_NAME Vibe3D), so the build emits Vibe3D.exe directly and blender.exe never exists. The "Rename to Vibe3D.exe" step does Get-ChildItem -Filter blender.exe and throws "blender.exe not found" — killing an otherwise good 2–3 h build.
  2. scripts/apply-msvc-patches.py is untracked and never called. The C5287 fix (MSVC 19.51 promoting enum-flag OR warnings under /WX) never reaches CI. It must be committed and wired into the workflow.
